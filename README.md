## 👉 (1) MAC(Multiply-Accumulate) 연산이 무엇이고, AI에서 왜 중요한지 설명할 수 있다.   
1. MAC 연산이란?
  MAC(Multiply-Accumulate) 연산은 곱셈(Multiply)과 누적 덧셈(Accumulate)을 수행하는 연산입니다.

AI 신경망에서는 입력값에 가중치(Weight)를 곱하고 그 결과를 누적해서 더하는 데 사용됩니다.
가중치는 각 입력값이 계산 결과에 얼마나, 어떤 방향으로 영향을 미치는지 조절하는 값으로, 일반적으로 학습 과정에서 조정됩니다.

AI는 학습 과정뿐 아니라 학습된 모델로 새로운 데이터를 처리하는 과정에서도 이러한 계산을 대량으로 반복하기 때문에 MAC 연산이 중요합니다.
   
   MAC(Multiply-Accumulate) 연산은 입력값과 가중치를 곱하고, 그 결과를 누적해서 더하는 연산이야.
AI에서 중요한 이유는 신경망이 여러 입력값에 가중치를 적용해 계산하는 과정을 대량으로 반복하기 때문이야.
   MAC는 두 가지 연산을 합친 것. (곱셈과 덧셈을 반복하는 연산)
 - Multiply(곱하기): 두 숫자를 곱한다.
 - Accumulate(누적하기): 곱한 결과를 기존 합계에 계속 더한다. (누적해서 더하기)

   
   <img width="587" height="218" alt="image" src="https://github.com/user-attachments/assets/2498a795-b465-48a1-a1d5-9f22ef0a3254" />
   입력값(Input): AI가 전달받은 숫자
가중치(Weight): 각 입력값이 결과에 미치는 영향을 조절하는 숫자
곱셈(Multiply): 입력값 × 가중치
누적(Accumulate): 곱한 결과들을 계속 더하는 것

AI는 가중치를 어떻게 정할까?

사람이 모든 가중치를 직접 정하는 것이 아니라, 일반적인 신경망에서는 학습 과정을 통해 가중치를 조정해.

그래서 MAC 연산이 AI에서 중요해지는 거야. 학습할 때도, 학습한 AI가 새로운 데이터를 처리할 때도 이런 계산이 반복적으로 사용되거든.
가중치(Weight): 입력값에 곱해서 계산 결과에 미치는 영향을 조절하는 개별 숫자

## 👉 (3) data.json의 “키 규칙/라벨 규칙”을 해석하고, 프로그램 내부에서 라벨을 표준화(정규화)하는 이유를 설명할 수 있다.  

## JSON의 키 규칙과 라벨 규칙 및 정규화

### 1. 키(Key) 규칙

JSON은 데이터를 `키(Key): 값(Value)` 형태로 저장하는 형식이다.

본 프로젝트의 `data.json`은 `meta`, `filters`, `patterns`로 구성되어 있다.

- `meta`: 데이터 버전 및 형식 정보
- `filters`: X, + 모양을 판별하기 위한 필터 데이터
- `patterns`: 판별 대상인 입력 패턴과 정답 라벨

**키 이름 규칙**

| 키 | 의미 |
|---|---|
| `size_5` | 5×5 크기의 필터 |
| `size_13` | 13×13 크기의 필터 |
| `size_25` | 25×25 크기의 필터 |
| `size_5_1` | 5×5 크기의 첫 번째 입력 패턴 |
| `size_13_2` | 13×13 크기의 두 번째 입력 패턴 |
| `size_25_1` | 25×25 크기의 첫 번째 입력 패턴 |

필터는 `size_크기`, 입력 패턴은 `size_크기_번호` 형식으로 구분한다.

### 2. 라벨(Label) 규칙

라벨은 입력 데이터가 어떤 모양인지 나타내는 분류값이다.

본 프로젝트에서는 X 모양과 + 모양을 판별한다.

| 구분 | 필터 이름 | 정답 라벨 |
|---|---|---|
| X 모양 | `x` | `x` |
| 십자 모양 | `cross` | `+` |

- `input`: 판별할 입력 패턴의 숫자 배열
- `expected`: 입력 패턴의 정답 라벨

### 3. 라벨 정규화(Normalization)

라벨 정규화란 같은 의미를 가진 데이터를 프로그램 내부에서 동일한 형식으로 통일하는 과정이다.

본 프로젝트에서는 십자 모양을 필터에서는 `cross`, 정답 라벨에서는 `+`로 표현한다.

파이썬은 문자열을 비교할 때 서로 다른 문자열을 구분하므로 다음과 같은 문제가 발생한다.

```python
print("cross" == "+")  # False
```

두 값은 같은 십자 모양을 의미하지만 문자열이 달라 비교 결과가 `False`가 된다.

따라서 프로그램 내부에서 라벨을 통일하여 비교해야 한다.

**정규화 예시**

```python
label = "cross"

if label == "cross":
    label = "+"

print(label == "+")  # True
```

위 코드는 `cross`를 `+`로 통일하는 예시이며, 실제 프로그램의 정규화 구현과는 구분된다.

### 4. 라벨 정규화가 필요한 이유

같은 의미의 데이터라도 표현 방식이 다르면 프로그램에서 서로 다른 값으로 판단할 수 있다.

따라서 라벨을 정규화하면 다음과 같은 장점이 있다.

- 같은 의미의 라벨을 일관되게 처리할 수 있다.
- 문자열 표현 차이로 인한 비교 오류를 방지할 수 있다.
- 예측 결과와 정답을 정확하게 비교할 수 있다.
- 분류 정확도를 올바르게 계산하는 데 도움이 된다.

**정리**

JSON의 키 규칙은 데이터를 일정한 형식으로 구분하고 관리하기 위한 규칙이며, 라벨 규칙은 데이터의 정답이나 분류를 표현하는 기준이다.

라벨 정규화는 같은 의미를 가진 데이터의 표현 방식을 통일하여, 프로그램이 예측 결과와 정답을 일관되고 정확하게 비교하도록 하기 위해 필요하다.






## 👉 (4) 부동소수점 오차가 판정에 어떤 영향을 주는지, 그리고 허용오차(epsilon) 기반 비교 정책이 필요한 이유를 설명할 수 있다.  

## 부동소수점 오차와 허용오차(epsilon) 기반 비교

### 1. 부동소수점 오차란?

부동소수점(Floating Point)은 컴퓨터에서 소수를 표현하는 방식이다.

컴퓨터는 일반적으로 숫자를 2진수로 저장하는데, `0.1`, `0.2`와 같은 일부 소수는 2진수로 정확하게 표현할 수 없어 가장 가까운 값으로 저장한다.

이 과정에서 발생하는 아주 작은 차이를 **부동소수점 오차**라고 한다.

```python
print(0.1 + 0.2)
# 결과: 0.30000000000000004
```

수학적으로는 `0.1 + 0.2 = 0.3`이지만, 컴퓨터에서는 소수를 근삿값으로 표현하고 계산하기 때문에 미세한 오차가 발생할 수 있다.

### 2. 부동소수점 오차가 판정에 미치는 영향

파이썬의 `==` 연산자는 두 값이 정확히 같은지 비교한다.

```python
print(0.1 + 0.2 == 0.3)
# 결과: False
```

두 숫자는 거의 같지만, 실제 저장된 값에 미세한 차이가 있어 `False`로 판정된다.

Mini NPU 프로젝트에서도 MAC 연산을 통해 입력 패턴과 필터를 곱하고 더하여 점수를 계산한다.

이때 부동소수점 오차가 발생할 수 있으며, 계산 결과를 기준값과 정확히 일치하는지 비교하면 미세한 오차 때문에 잘못된 판정이 발생할 수 있다.

### 3. 허용오차(epsilon)란?

허용오차(epsilon)는 두 숫자의 차이가 일정 범위 이내라면 같다고 인정하기 위해 설정하는 기준값이다.

예를 들어 허용오차를 `0.001`로 설정하면 두 숫자의 차이가 `0.001` 이하일 때 같다고 판정할 수 있다.

```python
a = 0.3
b = 0.3001

epsilon = 0.001

print(abs(a - b) <= epsilon)
# 결과: True
```

- `abs(a - b)`: 두 숫자의 차이의 절댓값
- `epsilon`: 허용할 오차의 범위
- `<=`: 차이가 허용오차 이하인지 비교

두 숫자의 차이는 약 `0.0001`로 허용오차 `0.001`보다 작기 때문에 `True`가 된다.

### 4. 허용오차 기반 비교 정책이 필요한 이유

부동소수점 연산에서는 아주 작은 오차가 발생할 수 있으므로, 모든 계산 결과를 `==`로 비교하는 것은 적절하지 않을 수 있다.

따라서 허용오차를 설정하여 미세한 계산 오차를 허용하는 비교 정책이 필요하다.

다만 허용오차를 너무 크게 설정하면 실제로 다른 값까지 같다고 잘못 판정할 수 있으므로, 계산 결과의 크기와 판정 목적을 고려해 적절하게 설정해야 한다.

### 5. 정리

**부동소수점 오차**는 컴퓨터가 일부 소수를 정확하게 표현하지 못해 계산 과정에서 발생하는 미세한 차이이다.

이 오차로 인해 거의 같은 숫자도 정확한 값 비교에서는 다르다고 판정될 수 있다.

따라서 **허용오차(epsilon) 기반 비교 정책**을 사용하여 두 값의 차이가 허용 범위 이내인지 확인함으로써, 미세한 계산 오차로 인한 잘못된 판정을 방지할 수 있다.
